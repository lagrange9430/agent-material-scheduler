## 2. 分工

**本人（候选人）决定的：**

1. 选题：四道题里选题目 1，理由是验收点可做确定性判定（见对话记录）。
2. 先做需求对齐再写代码，明确"哪些要评审拍板、哪些按推荐默认"。
3. 否决/确认了三处设计判断：硬约束阻断不存草稿、增加 hard 用例、中文文案 + 英文字段。
4. 提供模型接入信息，并确认最终交付形态（本地建仓 + 自行 push）。

**AI 生成的：**

- `src/` 全部代码、`tests/` 全部用例、`data/` 合成数据、`examples/` 运行产物；
- `docs/01`~`05` 与 `README.md` 初稿；
- 排查执行过程中的报错。

**本人验证的：**

- 逐条运行 `examples/` 下的命令，核对输出与预期；
- 在真实模型路径下抽查 trace，确认模型确实在根据工具返回调整动作；
- 确认没有任何"已发布"语义、没有真实密钥入库。

## 3. AI 实际犯的 5 个错（都被发现并修正）

| # | 错误 | 怎么暴露的 | 修正 |
|---|---|---|---|
| 1 | 直接把 `deepseek-v4.1-flash` 写进配置 | 第一次连通性测试返回 400：`The supported API model names are deepseek-flash, deepseek-v4-pro` | 改为 `deepseek-flash`；并把"先探测 `/models` 再写代码"作为固定步骤 |
| 2 | JSON 解析用 `find("{")` + `rfind("}")` 截取 | a1 首次 llm 运行直接 `failed`：`Extra data: line 1 column 89`——模型一次回了两个 JSON 对象，被拼成非法串 | 换成 `JSONDecoder().raw_decode`，只取第一个完整对象 |
| 3 | 阻断结论直接引用模型自由文本 | a4 的 llm 结论写成"16:00 无可用时段"，但模型根本没调 `query_slots`，属于幻觉 | 结论改为只由观测事实拼装（规则 ID、占用事实），模型理由仅保留在 trace |
| 4 | 终止动作没有走状态落账 | a7 的 `slot_status` 显示 `not_checked`，实际冲突已确认 | 终止动作也执行 `_apply_decision_side_effects`；并从 `query_slots` 观测反推时段状态 |
| 5 | 幂等挡住了"用户确认改期" | 带 `--approve` 重跑只返回 `duplicate`，草稿仍是待确认 | 改为同一幂等键下就地更新 `revision+1`，并禁止把已确认草稿降级回待确认 |

第 3、5 条是最有价值的：**它们不是语法错误，而是语义错误**——代码能跑、测试能过，但结论是错的。这也说明为什么"跑通"不等于"对"。

## 4. 如何验证 AI 产出（可复现的检查清单）

| 检查 | 命令 / 方式 | 判据 |
|---|---|---|
| 功能正确 | `python3 -m unittest discover -s tests -t . -v` | 40 个用例全绿 |
| 决策是真决策 | 跑 a2 与 c1，对比动作序列 | 仅改排期表，动作从"请求确认"变成"直接保存" |
| 没有越权发布 | `grep -r "publish" src/` + 扫描输出 | 工具表只有 4 个；输出无 `published` / "已发布" |
| 失败不虚报 | a6：注入 `save_draft` 故障 | 返回 `failed`、无 `draft_id`、草稿数不增 |
| 幂等真实 | a2 连跑两次 + 检查 `drafts-snapshot.json` | 草稿数不变，ID 相同 |
| 硬约束不被改 | a7 + `test_hard_constraint_guard_blocks_rescheduling_policy` | 不给替代时段、不落草稿 |
| 密钥不入库 | 检查 `.gitignore` 与 `.env.example` | `.env` 被忽略；示例文件值为空 |
| 模型确实在工作 | 抽查 `examples/trace/llm-*.jsonl` 的 `reason` 与 `next_action` | 依据引用上一步的真实返回 |

## 5. 我保留了哪些 AI 不擅长的判断

1. **"待确认"到底该不该落草稿**：AI 一开始倾向"待确认就不存"，我按业务语义选择"存草稿但标未确认"——因为运营需要看到具体时段才能决策。
2. **替代时段优先往后还是往前**：AI 给了"晚优先"，我确认保留，理由是发布节奏向后顺延更安全。
3. **是否为了好看加 HTTP 层**：明确拒绝。题目说 CLI 即可，加接口只会稀释对核心链路的注意力。
